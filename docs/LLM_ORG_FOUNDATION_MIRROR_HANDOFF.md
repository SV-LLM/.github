## Scope

This repository is the organization coordination surface for the proposed SV-LLM architecture. The initial change documents organization responsibilities and boundaries only.

## Canonical requirements

1. Intelligence participation does not confer governance authority.
2. Canonical ecosystem context is resolved through existing InTr/evidence paths rather than copied into provider repositories.
3. Cross-ecosystem repairs require applicable purpose/contract reconstruction.
4. Sandbox contributions remain independently attributable.
5. Disagreement, refusal, and uncertainty remain reconstructable.
6. Evidence provenance remains transitive across derived claims and synthesis.
7. `OBSERVED`, `DERIVED`, and `PROJECTED` states remain distinct.
8. Ecosystem AI performs evidence/receipted-history matching rather than model-style interpretive judgment.
9. The Inference Window is disposition-complete for every disposition available in the applicable Admissibility Matrix.
10. Provider/entity capability selection creates no authority hierarchy.
11. Existing LLM-adapter provider routing/transport/distributed-workload responsibilities are reused.
12. Existing Task Registry, WorkerCoordinator, Interlock/InTr, SDK, TV/TVC and Publisher authorities, and Master Records organization records and reconstruction, remain unchanged.

## Initial repository direction

As entity/provider repositories are added, they should expose provider-specific capability/interface declarations rather than duplicate the ecosystem's canonical knowledge or governance machinery.

The organization-level coordination layer should eventually provide machine-readable schemas for:
- capability declarations;
- work-context references;
- Sandbox work objects;
- attributable contributions;
- provenance chains;
- epistemic state;
- disposition-complete Inference Window projections;
- governance handoff references.

## Deferred integration

The Ecosystem Chat -> SDK Manifest Builder -> SV-LLM -> governance -> Publisher -> SDK return loop remains a secondary integration objective and is not claimed by this architecture PR.

## Completion of this PR

This PR is complete when the organization architecture and authority boundaries are reviewable from SV-LLM/.github. It makes no claim that the runtime, Sandbox, capability resolver, provider repositories, or consumer integration have been implemented.
